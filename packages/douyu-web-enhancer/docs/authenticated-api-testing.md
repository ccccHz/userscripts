# 登录态接口实测指南

本指南用于需要复用用户真实 Chrome 登录态、Cookie 或页面身份，但又不能仅靠静态源码判断的斗鱼接口。
目标是用最短路径取得可信的传输、业务和账号状态证据，同时避免泄露凭据、重复账号动作或把临时探针留进正式功能。

## 先判断测试路径

1. 先从归档源码、当前实现和 DevTools Network 确认接口 URL、方法、参数、请求头、预期收益与副作用。
2. 同源且浏览器允许的只读请求，可直接在页面 Console 用 `fetch`，再由 Network 和返回体交叉验证。
3. 跨域请求若被 CORS 拦截，不把它判为接口失效；应改用 userscript 已获授权的
   `GM_xmlhttpRequest` / `GM.xmlHttpRequest` 请求适配器。
4. DevTools 负责观察真实页面、Network、Console、响应和动作前后状态；它不应被强行当作跨域请求执行器。
5. 需要重复测试时，优先建设受控的 DEV 诊断入口；一次性测试尚无入口时，将最小探针放在独立诊断模块，
   不混入业务 runtime，验证后立即移除。

## DEV 诊断入口约束

- 只存在于 DEV 构建，正式产物不可调用。
- 默认不执行；必须显式给出接口名和最小目标，例如单个 `roomId`。
- 执行前返回请求预览；签到、关注、送礼、领取等奖励或账号写操作必须在动作发生前取得用户明确授权。
- 单次执行并防重复，不批量遍历房间或账号。
- 复用现有请求适配器和权限，不为测试临时扩大 `@connect`、`@grant` 或 `@match`；确需扩大时另行确认。
- Cookie、token、UID 等只在隔离执行上下文内使用，不写控制台、不写 DOM、不复制到文档；结果日志必须脱敏。
- 以 Promise 等待明确的完成、失败或超时结果，不在派发事件后立即读取可能尚未写入的字段。

理想调用形式：

```js
await __douyuWebEnhancerDev.probe("sign-room", {
  roomId: "5135383",
  dryRun: false,
});
```

这只是接口形状示例，不表示当前项目必须永久暴露该全局对象。实现时仍应使用白名单探针、参数校验和
DEV 构建门禁，不能提供任意 URL、任意请求头或任意脚本执行能力。

## 一次测试的完整证据

每次记录以下四层结论，不能互相替代：

1. **请求是否真正发出**：方法、目标 host、最小参数和次数；不记录敏感头原文。
2. **传输结果**：HTTP/网络成功、CORS、超时或被扩展拦截。
3. **业务结果**：接口自身的 code/error/message/data；传输成功不等于业务成功。
4. **账号结果**：动作前后任务、奖励、关注或签到状态是否发生预期变化；若业务明确失败，不重复调用求证。

DevTools 中同一时间出现的斗鱼官方请求、广告请求或扩展拦截错误不能自动归因于探针。应以目标 endpoint、
触发时间、请求方法和探针返回值共同识别。

## 收尾

- 移除临时探针、全局 hook、DOM 桥和敏感调试输出。
- 重建 DEV 产物并刷新目标页，确认临时入口已不存在。
- 运行与改动相称的类型检查和测试；若其他既存测试失败，单独标注，不能混成接口结论。
- 将结论更新到 feature 契约、验收记录和迁移清单；已明确下线的接口从 TODO 和运行时代码中移除。

## 已验证案例：`sign-room`

2026-09-19，在用户授权后使用已登录 Chrome 对房间 `5135383` 单次调用归档 Android checkIn 接口。
页面 `fetch` 因 CORS 失败，改由现有 userscript 跨域请求适配器执行；传输成功，业务返回
`{ error: 8, msg: "功能已下线", data: null }`。据此确认它是已下线的直播间等级签到，不是视频页或
实时回放能力，并决定不迁移。完整证据见 [verification.md](verification.md)。
