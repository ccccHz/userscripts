# 斗鱼网页增强架构

`douyu-web-enhancer` 是一个自用、单产物 userscript。源码按功能拆分，构建后不从网络下载
模块，不提供在线插件仓库或运行时热部署。

## 核心边界

- **Feature runtime**：统一启动、幂等启用、停用和清理功能。
- **Settings store**：只保存带 schema 版本的用户设置，异常数据回退到安全默认值。
- **Selector registry**：为易变 DOM 提供语义化选择器组，诊断信息记录实际命中的候选项。
- **Observer hub**：整个脚本共享一个 `MutationObserver`，对高频 DOM 变化延时合并并限制扫描频率。
- **Style registry**：只管理脚本自己创建的 style 元素；停用功能时完整撤销。
- **Diagnostics**：提供功能状态、命中选择器和错误摘要，可从油猴菜单复制。
- **Page controls**：承载高频功能的页面内入口，尽量复用旧版位置、用语和状态反馈；
  Tampermonkey 菜单不作为页面高频功能的默认控制面。

## 迁移契约

“功能已迁移”同时要求行为、入口位置、操作路径、状态反馈、默认值和持久化方式达到约定。
内部模块可以重写，但归档版经过长期实际使用验证的用户体验是默认验收基准。斗鱼 Web 没有
发生阻断性变化时必须等价迁移，不以新架构为理由重新设计。确需省略或重新设计时，先在
  `docs/migration/features.json` 的 `contract.deviations` 中登记提案、证据、目标和回退方案，取得
用户确认并记录后才能实施。未获确认的差异视为迁移缺口，而不是架构优化。

迁移清单同时描述两个层次：

- **体验组合**：用户感知到的一套完整能力，例如“简洁模式”。它可以跨越多个内部模块，定义
  必须共同成立的布局、入口、保留信息和状态矩阵。
- **原子功能**：独立设置、独立生命周期和独立测试的代码能力。体验上成组不要求内部耦合，
  但也不能因代码解耦而丢失原版组合体验。

实机验收以归档代码、原版实际页面截图和操作记录为基准。验收既检查目标元素是否生效，也检查
相邻区域没有被误伤，例如隐藏礼物展示栏时仍保留钱包/背包功能栏，隐藏排行榜时仍保留房间
统计摘要。

## 功能生命周期

`disabled → starting → waiting/active → disabled`；启动异常进入 `error`。每个功能必须能在
同一页面中反复启用和停用，不依赖刷新完成清理。

Observer 回调内所有可观察 DOM 写入必须先比较旧值，以保证幂等。不允许“扫描 → 写入相同值 →
再次扫描”的自激循环；即使单个功能误写，Observer hub 也不得用连续微任务阻塞页面渲染。

## 发布边界

新 package 默认设置 `userscript.publish=false`。这会让全工作区构建和检查覆盖它，但
`prepare-pages` 不会把它放进 GitHub Pages。完成真实斗鱼页面验证、权限审查和用户确认后，
才可单独开启发布。
