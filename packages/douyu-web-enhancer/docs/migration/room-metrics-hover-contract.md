## 用户目标

- 主统计栏人数部分改成“直观的人群/观众图标 + 在线人数”，不再并列贵宾项。贵宾、钻粉、数据口径与新鲜度等附加信息放人数hover；礼物收入、已观看等原有其它摘要项不因本修正删除。
- 用户称“真实人数”，但现有数据仍是 `oun/oul.un` 的在线榜口径，尚未有移动端同房同时段/官方完整观众口径证据。视觉布局可以立即改，label继续诚实使用“在线用户/在线人数”，不得把改显示方式当人数真实性认证。
- 当前代码中V形图标属于贵宾项；不再常驻展示该项，并为人数使用清晰双人/人群轮廓SVG，16px附近与原统计栏一致，不需要远程图片或新增依赖。
- 人数与观看时长共享悬浮层行为：鼠标保持在对应触发区域时持续显示，焦点保持时同样持续；不是出现几秒后消失，也不是永远固定显示。离开触发区/可读悬浮区域、失焦、停用或锚点被卸载才退出。两项内容不能串台。
- 人数触发范围覆盖图标、数字及适当padding，而不是仅图标或一小段文字。保持统计栏整体紧凑，不挡住旁边入口；键盘可聚焦、role/aria可读。

## 当前实现的直接线索

`src/features/room-metrics.ts`：

- metricsMarkup分别生成online和nobles项，后者是V形SVG。
- showTooltip没有“几秒后hide”的定时器；mouse leave/blur会关闭。
- 代码在 `document.addEventListener("scroll", hideTooltipOnViewportChange, true)` 捕获任意后代scroll，包括聊天列表自动滚动，因此鼠标未离开触发区也可能关闭，且不会再次产生mouseenter自动恢复。该因果线索须在真实页面验证，不能凭源码就声称现场根因已完全认证。
- CSS item没有扩大padding，tooltip为pointer-events:none；人数和时长使用同一个悬浮层。
- 每秒renderTimes更新文本和aria，共享ObserverHub可能执行mount；更新不得打断悬浮/重建鼠标命中区域。

## 实现要求

1. 保留原数据来源、未知与0的区分、换房清空和断线/180秒过期语义，不增加接口请求或Socket。
2. 维护明确的当前锚点与内容来源，避免频繁刷新关闭悬浮；人数和时长切换时准确更新。
3. 聊天区域自动滚动不能关闭仍被hover/focus的提示。只有可能使锚点位置变化的滚动/resize才按需重定位/关闭；采用有界调度，不给高频聊天scroll引入无限查询或逐消息DOM测量。
4. 内容保持实时更新但不改变触发区域；必要时支持移动到悬浮层继续阅读，鼠标完全离开才关闭。有离开延迟时必须有界/可清理，不使用持续秒数限制。
5. 停用、pagehide、挂载重建要移除自身节点和监听，幂等恢复；不泄漏观察者，不扩大用户脚本权限。

## 验收

先核对当前目标真实DOM/布局，然后在最新dist刷新后验证：仅人群图标+人数常驻，贵宾等只在hover；在图标、数字和padding各位置可触发；鼠标保持至少15–30秒且聊天持续自动滚动时人数/时长提示保持并正常更新；移开/失焦可退出；两项切换内容正确；刷新、停用/重开、换房/DOM重建不残留。用户手感反馈可以作为证据，不要求为形式重复已完成的页面路径。

自动化覆盖hover/focus生命周期、无关滚动不关闭、锚点失效清理、文本刷新不重建触发节点和位置/可见状态恢复。之后运行仓库 validate/test/type-check/build。不能只增加CSS或给showTooltip去掉不存在的倒计时后宣称修复完成；浏览器不可用时记录verifying缺口。保持当前版本与publish=false，不发布/安装/账号写入。
