# 活动弹幕：Socket 层过滤契约

## 2026-10-19 回看可读性

用户要求补充发送者身份、消除重复活动名。新记录从原包提取 `nn` 与合法数字 `uid`，与既有时间、房间和截短正文一同保存，仍只保留最近 50 条；无需查询用户 API。旧记录缺少身份时明确显示“旧记录未保存昵称”，不回填猜测身份。列表按昵称、年月日时间/房间、正文分行展示，类型与正文相同时不重复展示。过滤命中规则不变。

## 2026-10-18 误屏蔽防护与回看

- Socket 过滤保持默认关闭，仅匹配完整 `chatmsg` 中唯一的 `type`、`rid`、`gadid` 和 `txt` 字段；房间必须是当前房间，活动编号只接受已核实的 29/48。缺字段、重复字段、未知活动、正文关键词相同但无活动编号时全部放行。
- 完整帧校验失败、非支持数据类型、解析或改写异常一律保留官方原包。混合帧只移除目标消息，普通弹幕和控制消息保留；过滤记录与计数回调异常不得影响其交付。
- 现有房间/累计计数继续保留。新增本机最近 50 条实际过滤记录，展示时间、房间、活动类型与截断正文，供用户回看误判；未命中的普通弹幕不进入此记录。原有计数中包含早期 DOM 隐藏阶段，不能把历史总数解释成纯 Socket 过滤量。
- 飘屏装饰和特殊背景的进一步 Socket 过滤降低优先级，先积累同一消息到 DOM 的配对证据，不扩展当前活动规则。

## 已知事实与目标

- 当前 `activity-link-cleanup.ts` 用 `.Barrage-listItem:has(.js-barrage-activity-link[data-btype=...])` 的 CSS 隐藏整行；统计来源是渲染后的 DOM，不是网络消息。因此飘屏仍会收到活动消息。
- 当前 `main.ts` 接入的 Socket 过滤只有按 UID 屏蔽普通 chatmsg 和可选 uenter，活动开关没有进入过滤路径。
- 自然采样与模板已有证据：`chatmsg.gadid=48` 为合成大西瓜，`chatmsg.gadid=29` 为保卫鱼娘。实施前复核既有样本与官方模板/当前页面消息流，不把普通用户正文中的活动名称或一般链接当特征。
- 新的可见成功结果：开关开启后，已确认的活动消息在官方页面业务监听器收到以前被过滤；右栏不生成对应新行，播放器不生成对应新飘屏。不得仅增加第二套飘屏 CSS 后声称实现了 Socket 过滤。

## 开关与行为

1. 复用已有 `features.activityLinkCleanup`、入口和持久化，保持默认关闭和旧设置导入默认值，不新增独立飘屏开关。
2. 独立于用户屏蔽：没有 UID 名单、关闭 UID 屏蔽时，活动开关也必须生效；活动和 UID/进场规则组合时不互相覆盖。
3. 精确过滤当前已核实的两类活动，普通 chatmsg、正文仅提“大西瓜/保卫鱼娘”、普通链接、其他/未知活动、礼物/进场/控制消息原样保留。
4. 同一帧含活动与普通消息时仅删除目标业务消息，保留消息原有顺序、帧协议和投递行为；无目标时保持原始数据。不能整帧误删、丢控制帧或使心跳/重连失效。
5. 关闭开关后新到活动消息按官方路径正常交付。不重放此前已丢弃的消息；已显示或排队的旧消息另有生命周期，不能把开启后的短暂旧队列显示当新消息过滤结果。
6. 不创建额外 Socket，不发弹幕/送礼/关注/封禁，不读取 Cookie/Token，不修改官方账号屏蔽设置，不扩大 userscript 权限。

## 统计与其它观察者

- 保留既有总数/房间/最后时间的存储，不能清除用户历史。新增计数的口径改成实际被过滤的活动业务消息，而不是隐藏 DOM 行；UI/契约须解释旧统计与新口径的边界。
- 只在实际成功拦截后累计；同一消息同时命中 UID 和活动规则不能在同一活动统计里重复累计，也不能当作两条官方消息。DOM 兼容兜底若保留，不能形成第二来源重复计数。
- 保持本房间、跨房间和多标签事务累加、刷新恢复、计数写失败重试语义。统计库仍只保存房间号、计数与时间；2026-10-18/19 新增的独立有界回看库存储范围以上方更新为准，不保存完整原包。
- 已有关注记录、弹幕速度、房间管理事件等过滤前只读观察者保持既有语义和失败隔离；不要把“屏蔽官方显示”扩大为删除用户自己的其它记录。

## 失败与覆盖边界

实施前核对聊天栏和播放器实际使用的连接、运行上下文、消息类型及 binaryType。现有 Hook 的 ArrayBuffer、非支持数据类型、跨事件分片/无效帧保守放行逻辑要逐一审查；不能忽略它们却写“两个区域保证覆盖”。若目标消息实际走了 Blob、包装类型、其它页面连接或播放器独立上下文，应补足相应路径或明确报告具体缺口，而不是假定覆盖。

保留对无关/畸形消息的安全行为、有限内存和诊断。统计/记录回调异常不能破坏原生普通消息投递；合成 message event 不应递归过滤或重复观察。无法安全过滤时有明确 skipped/error 诊断，不声称已经阻断。
