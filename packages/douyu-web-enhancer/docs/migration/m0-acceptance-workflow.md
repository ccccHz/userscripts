# M0 验收工作流复盘

最后更新：2026-09-04

## 本次成本记录

| 项目 | 结果 | 成本/重复 |
| --- | --- | --- |
| 源码、版本、预览包和 worktree 确认 | 手动读取一次 | 低；后续任务仍必须保留。 |
| 全量门禁 | 4 条命令；148 个测试 | 约 12 秒；只应在体验组合里程碑执行。 |
| 普通页组合 | 4 个代表性状态 | 足以覆盖三个独立开关的主要 pairwise 关系，无需穷举 8 种。 |
| 刷新、换房 | 各一次 | 固定房间转为未开播导致一次失败和一次换房恢复。 |
| 两类全屏 | 各一次进入/退出 | 强制点击产生歧义；改用可见控件后成功。 |
| 页面结果采集 | 计算样式、几何和入口状态合并采集 | 同一证据可覆盖多个 feature，四层结论仍分别记录。 |
| 全量可访问性树 | 多次、包含大量动态弹幕 | 时间不高但 token 成本最高，且与验收目标无关。 |

本次真正昂贵的不是构建或图像处理，而是反复输出整页动态可访问性树、重新辨认哈希控件，以及在
未开播房间上重试。等待本身很少；失败点共两个：固定样本下播、强制点击无法可靠区分两类全屏。

## 调整后的流程

### 保留

1. 开始时一次性确认源码、版本、预览包、发布开关与工作区状态。
2. 迁移前基准卡片、三个代表性开关组合、刷新、换房、两类全屏、同页停用/恢复和相邻区域检查。
3. 以计算样式和几何为页面结果证据；用可见控件实际进入全屏，不用代码伪造页面状态。
4. 外部来源失败时验证降级和隔离，但成功数据没有出现就保持 `verifying`。

### 合并与减少

1. 一次页面快照同时采集开关、礼物行、播放器、榜单、活动区、弹幕高度、前缀、统计摘要和保留区；
   不为四个 feature 分别重复抓同一页面。
2. 独立开关采用全开、全关及两个代表性混合状态，不做 `2^N` 穷举；只有发现串扰才扩展组合。
3. 页面动作后优先读取窄 DOM/计算结果；仅在需要定位可见控件或验证交互反馈时读取可访问性树，且
   禁止把动态聊天正文纳入记录。
4. 单功能迭代只跑定向测试、类型检查和 package build；全仓四门禁只在 M0/M1 等里程碑跑一次。
5. 活跃房间从当前已打开页面选择，不把某个房间号永久写成测试前提；未开播只保留一次降级样本。

### 移交给用户的人工项

- 主观视觉等价、按钮是否容易发现、悬浮出现时机和常用缩放/显示器下的舒适度。
- 浏览器或操作系统阻止自动化进入原生全屏时，由用户点击一次并反馈；agent 继续采集退出后的结果。
- 外部统计服务长期不可用、SC 等罕见自然状态和真实账号相关结果，等待自然样本，不伪造或反复轮询。

## 后续验收预算

每个原子功能默认只允许一次源码基准、一次定向自动化、一次普通页实机和一次涉及的特殊模式实机。
只有出现与契约冲突的证据才扩大读取和状态矩阵。新功能另起任务时引用稳定 feature ID、本文件和
`features.json`，不携带整段历史对话；这既降低上下文压缩和 token 消耗，也避免旧的临时判断成为规则。
