# Socket 礼物与发弹幕研究交接（2026-10-14）

本文件只整理既有匿名收包与一次用户授权的真实发言测试。原包留在 `.local/socket-archives/`，这里不记录用户 UID、Cookie、完整消息正文或请求凭据。

## 礼物：已确认和边界

- 16 房分段采样的 `dgb` 收到 50,534 包、按配额保存 31,497 包，覆盖 14 房；早、午、晚、夜均有样本。`dgb` 是本房间礼物行为的候选消息，当前关注用户记录已经核对 `uid/rid/gfn/gfid/gfcnt`，用礼物名或编号和数量显示，不推断鱼翅价值。
- `spbc` 是跨房间礼物广播，不能并进当前房间的送礼统计或拿来判定某人在当前房间送礼。
- `ranklist` 收到 6,621 包、保存 6,578 包，16 房均见；包含 `list_day/list/list_all`，相邻列表内容有大量变化。这只能证明榜单有推送；尚未确认日/周/总时间口径、是全量还是增量，以及刚进房时的 HTTP 初始化来源。
- 单条 `dgb` 的连击、重复推送、撤回/修正、礼物单价与付费/免费分类尚未与官方页面及礼物表配对。因此不能把 `gfcnt` 直接累加为今日鱼翅收入，也不能用 `ranklist.gold` 替代今日礼物收入。
- 下一项目可从已保存原包做脱敏字段分布，再在一个固定直播房同步记录首屏 HTTP、`dgb/ranklist` 和官方礼物展示，按同一事件与时间戳配对。无需重做 24 小时采样；原采样有 2 小时 3 分钟无保证空档和若干调度/断线空档，不可视为完整连续流。

## 发弹幕：一次受控测试

- 用户明确允许在房间 `2016309` 发弹幕。2026-10-14 在内置 Browser 页面通过官方聊天输入框和发送按钮提交一条标明测试用途的普通弹幕，页面聊天栏随后出现该正文。
- 同次 DevTools 网络事件看到一个 opcode 2 二进制出站帧。标准斗鱼包头长度与实际 206 字节相符，STT 正文为 `type@=chatmessage`，字段名包括 `content/col/dy/sender/ifs/nc/dat/rev/tts/admzq/cst/pe`；`content` 含刚提交的测试正文。另有邻近 `mrkl` 心跳帧。没有看到对应 HTTP 弹幕发送请求。
- 因而在页面自己的 WebSocket `send` 前，限定 `type=chatmessage` 且完整合法的 STT 帧，改写 `content` 并重算包头长度，在技术上有明确入口。需要按 STT 规则转义 `/` 与 `@`，保持其它字段、帧顺序和类型；不完整、未知、超限或非本房消息原样放行。
- 本轮没有安装出站 Hook、没有改写发送包，也没有验证服务器对改写包的接受、长度上限、重复发送控制或登录态连接归属。因此这是可行性证据，不是“小尾巴已实现”的结论。归档 DouyuEx 的小尾巴改输入框后交由官方发送，不 Hook Socket。
