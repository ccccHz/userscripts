# 弹幕发送独立观察通道实现记录

状态：匿名只读 WebSocket 已获用户授权并在 `0.6.0` 实现；用户已实测确认可检测。
`0.7.0` 将有限观测记录升级为 IndexedDB 主存储、`localStorage` 故障回退；
登录态、Cookie/Token、自动发送及其他账号能力未授权。

## 为什么当前 DOM 不够

发送者页面在 2 秒内没有出现匹配的 `.is-self` 行，只能说明“页面未确认”。它可能来自发送失败、页面过滤、
DOM 延迟或选择器失效，不能证明其他观众看不到。`0.5.2` 曾把随后任意不匹配的本人行配给旧超时项；该关联
没有消息 ID 或独立观察证据，已在 `0.5.3` 删除。

证据等级固定为：

| 等级 | 最低证据 | 可用文案/行为 |
| --- | --- | --- |
| `unconfirmed` | 发送动作后 2 秒内没有同房间、同文本的本人 DOM 回显 | 只显示“未确认”，可本地记录，不能划线其他行 |
| `suspected` | 独立观察通道与发送动作、本人 DOM 行之间存在可复核的窄时间窗及稳定关联，且两边内容不一致 | 可在该指定行加虚线和“可能发送失败/被改写”，必须说明仍可能误判 |
| `proven-failed` | 带稳定消息 ID 的明确服务端拒绝，或同等强度且能唯一对应本次发送的证据 | 才能表述为发送失败；当前方案不假定能取得此证据 |

## 已授权的最小实现

1. 只建立归档同类的未登录、只读弹幕连接：`wss://danmuproxy.douyu.com:8502–8505`，发送协议所需的
   匿名 `loginreq`、`joingroup` 与心跳，不读取或派生 Cookie、Token、UID，不发送聊天或账号指令。
2. 连接仅在 `danmaku-send-check` 启用且位于数字房间时存在；换房先关闭旧连接再建立新连接，停用/pagehide
   立即关闭。端口重试、断线退避和最大重试次数必须有界，不增加永久轮询。
3. 只提取 `chatmsg` 的接收时间、房间和文本，不读取昵称或 UID。当前以发送动作、同房间、归一化文本、
   本人 DOM 行和 FIFO 次数关联；不使用用户名子串、任意下一条本人消息或 Cookie/Token。公共流中他人同文
   可能造成保守的漏报，但不会把不相关弹幕行标成失败。
4. 只有通过不同房间、同文重复、并发发送、他人同文、延迟/乱序、断线重连和 DOM 重建矩阵后，才允许产生
   `suspected`。任何候选后来被匹配回显或更强证据反驳时，立即恢复该行原有样式/title、移除附加文字，
   把本地事件改为已更正，并在发送区上方提示。
5. 本地数据仍限制为时间、数字房间、弹幕内容、证据等级与更正状态，最多 500 条；不保存昵称、UID、连接包、
   Cookie/Token，不上传。事件以 IndexedDB 为主存储并按时间、房间、证据和更正状态建索引；
   IndexedDB 不可用时回退到 `localStorage`，旧 GM 记录只补齐缺失 ID，迁移成功后置空旧 GM 事件数组。
   未来 UI 分析与导出另行设计。

## 继续保持的退出条件

- 若当前斗鱼协议必须使用登录态、Cookie/Token，或没有稳定关联字段，则停止在 `unconfirmed` 能力，不实现行标记。
- 不自动重发，不做真实账号操作，不把共享 WebSocket 顺带扩展给自动回复、禁言、送礼或其他功能。
