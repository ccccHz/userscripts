# 统一提醒与收件箱（2026-10-19 已冻结，验收中）

用户授权本轮仅统一提醒、增加记录与未读入口；不扩展 Socket、不改账号操作或既有记录开关。
本契约替代 socket-next-batch-design 中逐卡悬停、第四卡替换最旧及刷新清空未读的旧规定，
并替代 room-events-contract 的独立提醒栈描述。其他关注历史、事件日志和控制中心入口布局契约保留。

- 通用提示、关注和房间事件使用唯一 NotificationCenter，最多同时三张。通用 4500ms，关注与事件 15s。
  pointerenter 整个根容器（含卡间隙、绝对定位的汇总）暂停全部时钟；悬停期间不加入任何卡，
  即使不足三张也只累加溢出计数。离开恢复剩余时长。用户显式关闭/停用可以移除卡。
- 溢出只保留一个计数，不保存待弹逐条队列，不替换现存卡，不逐条补弹。汇总位于容器上方，
  不参与布局、不推移卡片；这一批卡全部结束后汇总消失。移除同步完成，无离场动画竞态。
- 符合提醒开关和关注规则的消息先写独立 NotificationInbox，再选择 Toast；仅记录开关命中的旧历史
  仍归旧模块所有。新收件箱是记录与未读唯一来源，独立同源 localStorage 键
  `douyu-web-enhancer:notification-inbox`，最多500条、7天，读写时裁剪。无空闲轮询。
  同步写成功才标记 saved；失败保留本页、标题入口及列表明确提示存储失败，不再创建故障提醒。
  该收件箱不承诺多个同时活跃页面的实时合并；既有关注和事件 IndexedDB 不删除、不迁移。
- 顶部「记录/未读 N」切换到独立记录视图，每批20条；每条提供明确标读。打开列表、到期和关闭卡
  均不标读。既有按用户标读作用于同一收件箱中的该关注用户记录，取消关注不删除收件箱。
- hidden 期间仍记录实际接收的合格提醒及未读，不弹卡；恢复 visible 只派生一次
  「离开期间有 N 条新提醒」。若悬停或满三卡，摘要显示在不占位汇总区域。重复 visibility 不重复计数。
  不补连接冻结期间未收到的消息；不新建 Socket、不保存普通全量弹幕。
- 预览明确标记「预览」，派生摘要明确标记「汇总」；两者不写真实记录、不增加未读，预览满额时不排队。
- 全屏时唯一根重挂到 fullscreenElement，退出移回 body。卸载移除根、监听器和有限到期时钟。

实现入口：`src/core/notification-{center,inbox}.ts`、`src/core/notifier.ts`、
`src/features/user-follow-reminders.ts`、`src/main.ts`、`src/ui/control-center.ts`。
自动化：`test/notification-center.test.mjs`（固定时钟、脱敏夹具）及既有关注消息测试。
真实证据和未覆盖项记录在 `docs/verification.md`。版本维持0.10.10，publish=false。

## 2026-10-19 UI 优化（用户追加授权）

- 提醒中心提供全部、关注、房间事件、系统四个类型入口，数量表示该类保留记录数；分类只改变展示，切换后恢复首批20条。
- 「全部标为已读」一次标读全部保留记录，不受分类或分页限制；没有未读时禁用。只进行一次存储写入，无新增提醒；写失败仍明确显示本页暂存。
- 单条使用紧凑分隔列表，类型/短时间/标读同一行，标题正文各自显示；未读小圆点、已读弱提示。移除逐条大卡边框、大按钮与重复的未读文案，说明收在底部。
- 本次不改变Toast容器、提醒规则、旧历史、保留上限或顶部入口拖拽与跟侧。

## 2026-10-20 轻量未读交互（用户确认，替代前两轮同范围约定）

- 分类各自提供「保留未读」，系统默认关闭、关注/房间事件默认开启；只影响新消息的初始read状态，旧未读不清除，Toast规则不变。
- 收件箱同一存储键升级为entries/preferences对象，兼容旧数组，无历史迁移丢弃；设置与记录一起保存，失败沿用明确本页暂存提示。
- Tab仅显示未读数量，零不显示。默认关闭「显示已读」；关闭保留未读的类别直接展示历史，不被该过滤隐藏。
- 控制中心打开且可见时，对滚动视口内标题至少一半可见的记录批量标读；未滚到、未加载不标读。标题作观察点避免长正文永远达不到阈值。
  本次阅读已看到的行保留，切换分类、关闭重开时重新过滤，防止阅读中突然消失。隐藏/关闭/卸载停用观察，空闲无轮询。
- 去掉逐条标读按钮。分类按钮为「关注全部已读」等，仅处理当前分类全部保留记录，全部tab覆盖全部分类；无未读时隐藏。

## 2026-10-20 面板关闭行为补充

提醒中心只在显式点击记录入口时进入，不参与整个面板关闭后的分区记忆。关闭时回到进入提醒中心前的普通分区（默认概览），防止重新打开控制中心就触发未读可视标读。普通分区仍保留记忆，重复点击记录入口不覆盖返回分区。用户页沿用通用面板半透明与模糊，不另设不透明背景。

## 2026-10-20 个人行为未读设置（用户确认）

- 保留原提醒开关与Toast语义。新关注用户不生成个人例外，发言/进场/礼物默认跟随关注分类（默认保留未读）；个人选择可覆盖分类，系统分类默认不保留未读保持不变。
- 每个UID的三个行为分别选择默认/保留未读/不保留未读；只决定后续实际合格提醒的初始read状态，不改已有未读、不改旧关注/事件历史、不因本功能捕捉额外消息。
- NotificationInbox同一存储对象增加followOverrides，唯一状态源；上限1000位，加载校验UID和行为布尔值。恢复默认移除该UID例外；取消关注不主动删除其偏好。未知行为/旧记录没有kind时沿用分类，绝不从标题猜行为。
- 新记录显式保存kind和nickname，Toast和收件箱共用同一消息。关注名单每人增加默认收起的「未读设置」，摘要显示例外；三列行为选择与恢复默认放在展开区，不挤占名单主要操作。
- 提醒中心的关注记录提供「未读设置」入口，打开单个用户共用编辑器并滚动到可见位置；关注分类另有默认收起的集中管理，支持昵称/UID搜索与每批20人，无消息的关注用户也可预先设置。两个入口读写相同配置，刷新保留。
- 设置写失败时本页继续生效，入口/编辑器明确提示未保存；无故障Toast递归。关闭未读并不等于关闭Toast。

## 2026-10-20 遗漏汇总计数修正

用户反馈：已关闭个人进场保留未读，回到页面仍出现汇总，但面板未读为0。原因是隐藏/溢出计数沿用全部实际消息计数，没有应用未读策略。现隐藏恢复摘要与「还有N条」仅统计接收时按分类/个人行为策略需要保留未读的消息。可见时原消息Toast不受影响；不保留的消息仍保存记录，但不再次以遗漏汇总打扰。


## 2026-10-22 三档行为提醒与前台待看修正（用户授权推进）

本节替代前述关注类别「保留未读」与个人布尔选择的界面契约。以用户 × 行为（发言、进场、礼物）统一选择不提醒、仅 Toast、Toast＋待看；个人可跟随默认或恢复默认。默认行为设置在用户页，提醒中心关注分类可搜索管理全部关注用户，单条记录也可进入同一编辑器。旧全局 Toast 开关不再作为另一层隐藏开关。

NotificationInbox 为模式与记录唯一状态源，同一存储对象增加 followDefaults，followOverrides 使用 off/toast/pending。首次迁移按旧行为开关与保留策略得出默认模式；旧个人 true/false 分别迁移 pending/toast，旧全局关闭的行为维持 off。迁移只执行一次，不改变已有记录 read 状态；全新安装三个行为默认 pending。个人设置不改变原始历史记录的独立保存选项。

新提醒接收时，document 可见且 hasFocus() 为 true 视为正在看，直接保存已看记录，不新增待看。离开时仅 pending 计入待看；off 不弹出、不入提醒中心，toast 弹出但不计待看或遗漏汇总。隐藏恢复与溢出汇总复用同一判定。提醒中心默认仅列待看，可主动显示已读；分类数字只计待看。可视标读也要求窗口焦点，focus/blur 驱动重建观察，无轮询。

验证：15 项定向测试覆盖三模式 × 可见/隐藏 × 聚焦/失焦、旧设置迁移一次性、记录保留、失败、汇总。内置浏览器隔离构造样本验证三档选择、用户差异与刷新持久化；真实斗鱼 /52 已检查最新主目录构建入口与默认设置。真实页面增强关注名单为 0，未通过新增真实关注或发送弹幕制造样本，自然关注用户消息路径仍待实测。版本保持 0.10.10，publish=false。
