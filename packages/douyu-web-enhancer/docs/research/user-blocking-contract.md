## 已确认事实

- 用户目标包含按数值用户身份屏蔽，规则可作用于所有访问的斗鱼房间或仅作用于指定房间。这里的“全房间”解释为本机脚本在逐个访问房间时生效，不意味着监听全平台所有房间，也不调用斗鱼服务端禁言。
- 既有页面 WebSocket Hook 只读取消息类型和连接计数，原样放行页面消息。匿名采样中，`182102` 的 547 条 `chatmsg` 均有数值 `uid` 与 `rid`，另有 211 条 `uenter`、15 条 `dgb`；`52` 还出现了带内层 `chatmsg` 的 `comm_chatmsg`。因此不能把全部可见文字等同于顶层 `chatmsg`。
- 2026-09-29 在 Chrome 房间 `182102` 读取实时 DOM：`#js-barrage-list` 中 85 条普通弹幕均有 `.Barrage-nickName.js-nick[data-uid]`，同一行内两个 UID 节点的值一致；四条非普通行未纳入。该房间当时未取得自然飘屏样本。
- 归档 DouyuEx 有去重复弹幕、去进场和背景等独立功能，未找到可直接复用的“按用户 ID 全局／单房间屏蔽”实现。当前代码的 `message-context-action-fallback` 可复用右栏与飘屏区域选择器，但其按作者／正文寻找消息的逻辑不能作为屏蔽身份依据。
- 同级旧 `socketHook` 证明曾尝试通过 `onmessage` 改写入站字节，但只包 `onmessage`、强制设置 `binaryType=arraybuffer`，并对未修改消息也重新编码。它是协议参考，不能原样复用。`douyu-ban/banBySocket.js` 只有构造器/实例 Proxy 探索，未形成可直接复用的可靠屏蔽器。
- 对已保存的 `182102` 样本按帧头定向计数：381 帧中 234 帧含多个协议包，133 帧同时含 `chatmsg` 与其他类型。整帧丢弃会误伤其他消息；每条目标消息须在保留同帧其余字节的前提下处理。
- 2026-09-29 一次性离线过滤试验（临时脚本，不进入安装包）：从 `182102` 自然样本内部选一名重复发言 UID，不输出 UID 或正文；381 帧中仅 7 帧需要变化，删去 7 条目标 `chatmsg`，其余 374 帧逐字节不变，保留的 794 条消息顺序与内容匹配预期。对房间 `52`，155 帧中 2 帧因协议包跨 WebSocket 帧而不能安全单帧过滤，试验选择原样放行；其他完整帧删去 4 条目标消息且无对照不匹配。这只证明离线字节操作可行，尚未证明真实页面的事件分发、右栏和飘屏结果。

## 已确认的首项行为

1. 默认关闭。用户明确添加数值 UID 后，在本机隐藏该 UID 的目标内容；不修改斗鱼账号的黑名单、房管禁言或任何服务端状态。
2. 每条规则选择“所有房间”或“当前房间”。有效规则为全局规则与当前房间规则的并集；跨房、刷新后继续生效，关闭功能或移除规则后，后续消息立即恢复原生接收。已被入站过滤的历史消息不会回填。
3. 第一项按 Socket 入站 `chatmsg.uid` 拦截普通文字弹幕，目标是让右侧弹幕和播放器飘屏同时消失。飘屏效果需要自然样本证明；进场、礼物、排行榜和系统行分别评估。若飘屏由其他消息类型/连接驱动，则继续取证，不靠昵称或正文模糊匹配。
4. 现有被动 Hook 保持第一阶段基线。活动拦截必须另设默认关闭的能力，针对目标 UID 的单条消息做最小变更，同帧其余消息及不认识的结构原样透传。右栏的 `data-uid` 可作为显示对照或安全回退，但不能拿其存在冒充 Socket 双区域覆盖的证明。

## 生命周期、失败与边界

- 只在数字直播页生效；SPA 换房重新计算当前房间规则。斗鱼自行断线重连不清空规则，也不由本功能建立第二条连接。拦截不可用时原生消息原样通过，并报告降级；是否启用右栏 `data-uid` 展示回退需明确标明它不能覆盖已验证之外的飘屏。
- UID 缺失、格式异常、区域不明或飘屏无法配对时不隐藏，避免误伤其他观众。设置失效时回退为原生展示；保留诊断计数但不记录昵称、正文或完整消息。
- 不扩大 `@match`、`@grant`、`@connect`；不读取 Cookie/Token、不发送弹幕、不调用关注/屏蔽/送礼接口。验证期保持版本 `0.10.10` 与 `userscript.publish=false`。
