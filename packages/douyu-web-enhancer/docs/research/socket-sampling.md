# 斗鱼 Socket 研究采样（匿名）

状态（2026-10-02）：短时、单房及多房长期采样器已实现。16 房匿名采集于 16:10:48 CST 启动，原进程在最后 17:19:58 状态之后退出，原因未确认；19:23:09 已续采，仍在翌日 16:10:48 截止，共用已授权 5 GB 总预算。两份目录均保留；存在采样空档，不称为连续完整 24 小时。页面登录态仅做过短时 CDP 只读观察，长期被动页面采集和首次榜单 HTTP 配对尚未实现。

## 目的与来源

先用独立 CLI 连接一个房间的 `danmuproxy.douyu.com` 公共弹幕流，记录自然收到的消息，按类型和字段结构分析。此工具不使用页面 Cookie、Token 或 UID，也不改 `douyu-web-enhancer` 的安装包。页面已安装的被动 Hook 保留为后续有争议时的定向对照。

同级历史项目 `Douyu-node` 区分登录态 `wsproxy` 和公共消息 `danmuproxy`，但其默认入口允许终端输入发送弹幕/礼物且保存 Cookie，因此仅参考协议，不运行原入口。当前公共流是否足以覆盖礼物、榜单、背景等需求，必须由自然样本决定。

## 短时工具：持久化选择

采用**逐帧 JSONL**，每行一个带时间戳的记录；入站帧以 base64 原样保存，供协议解析器以后重新分析。另提供 `analyze` 命令实时重算消息类型、包类型、字段名和值形状（空、数字、URL、文本、嵌套/转义）。不引入数据库依赖：当前只有单进程顺序写入、最多 10 分钟、32 MiB、20,000 帧；按类型索引可由原始数据重新生成。若将来需要长时间、多房间或复杂查询，再评估 SQLite。

文件默认位于 `packages/douyu-web-enhancer/.local/socket-samples/`，该目录被 Git 忽略；新目录权限为 `0700`，新文件为 `0600`。**原始帧可能包含聊天正文、用户标识和其他个人数据**，不要提交、分享或粘贴原文件；CLI 标准输出只有聚合摘要。数据不会自动删除或上传，后续清理须按仓库规则取得用户确认。

## 短时工具：运行边界

- 只连接指定的一个数字房间，连接建立前最多轮换四个端口，同一时刻至多一条连接；连接成功后断开即停止，不自动无限重连。
- 仅发送公共流连接必需的 `loginreq`、`joingroup` 和 40 秒一次的 `mrkl`。没有聊天、送礼或其他账号命令，也不扫码登录。
- 默认 120 秒，最大 600 秒；单帧上限 1 MiB，总入站数据上限 32 MiB、帧数上限 20,000。到上限、用户 Ctrl-C、断线或超时即关闭连接。
- 不与同房间登录态 CLI 连接并行。用户报告同账号同房间新连接可能顶掉旧连接；登录态测试进入单独阶段前沿用这一操作约束。

## 短时工具：命令

从仓库根目录运行：

```sh
node packages/douyu-web-enhancer/tools/socket-sampler.mjs capture --room 1126960 --seconds 120
node packages/douyu-web-enhancer/tools/socket-sampler.mjs analyze packages/douyu-web-enhancer/.local/socket-samples/<文件名>.jsonl
```

第一条命令结束时会打印本地文件路径与聚合摘要。第二条可在调整分析器后对同一份样本重新分析；`analyze` 不打开网络连接。

## 后续判断

1. 先分类消息类型及字段，识别礼物、榜单、进场、普通弹幕和无法解析的帧；未自然出现的类型标为缺样本。
2. 对用户屏蔽和关注，检查是否有稳定 UID 与房间标识；对链接、活动图标和装饰，检查字段能否识别对应弹幕。
3. 对背景、head、tail、头像，公共流字段只能证明“数据里有什么”；要判断最终渲染与极简模式无误伤，仍需选取自然消息与页面 DOM 定向配对。
4. 仅当公共流字段不足、发生难解释的 bug 或要全面评估页面控制消息时，再设计登录态采样。届时另行确认扫码或其他凭据方式，不复用或提交本工具的原始文件。

### 采集方式

1. 已实现匿名 CLI 长期观察指定的一个或多个房间公共流。下一阶段的页面采集器将被动复用用户
   已经打开的连接，补登录态专属消息及 DOM 配对；当前尚未实现，不新建带凭据的 Socket。
2. 两个来源分别标记，不能用公共流“没收到”断言页面流也没有。页面关闭后的采集盲区、Mac
   休眠、断网、重连次数和数据丢弃必须可见；不承诺完整平台历史。
3. 接收所有消息类型后分类：普通高频消息保留有限代表样本；目标稀有事件提高留样额度；
   未知类型和新的字段结构留样，不能只采已知事件名单。计数涵盖实际观察到的全部消息。
4. 长时模式与短时逐帧模式共存。短时原始帧继续无损重放；长时保留选中协议包的原始 STT
   和来源/时间/连接/序号索引，明确它不是完整原始 WebSocket 帧记录。解析错误只保存限量的
   错误码、帧序号和字节数，不保存整帧，以免混入登录确认字段。跨帧组包和嵌套转义已有测试。
5. 配置和皮肤决定最终表现，样本需关联官方静态配置的获取时间与内容哈希；仅保存消息字段
   无法长期还原活动展示。首次进入的榜单另补定向 HTTP 证据，不长期记录全部浏览器请求。

### 单房工具的资源边界

以下是保留的 `socket-archive.mjs` 单房模式；当前运行使用后文的多房模式与总预算。

- CLI 默认/最长 24 小时，可手动停止；按 10 分钟或 16 MiB 在下一条完整记录前分段。
  默认每次运行 256 MiB 磁盘预算，包含序列化开销并预留两份状态文件；达到预算停止并报告。
  旧目录不自动删除，预算不包含历史采集目录。
- 每个采集器同一时刻一条匿名连接；连接超时 15 秒，断线 1 秒起指数退避、最多 60 秒，
  整轮最多重试 20 次。没有常驻守护服务、开机自启或自动恢复已停止进程。
- 签名包括类型、顶层键与值形状、各嵌套字段的平面键集合，以及白名单中的活动/装饰数字 ID。
  不把正文、昵称、UID、消息 ID、房间 ID 当成结构变体；不是完整的嵌套路径索引。
- 普通类型每结构 10 包/每类型 200 包；目标候选每结构 100 包/每类型 5000 包，
  `ranklist` 每结构也允许 5000 包；未知类型每结构 10 包/每类型 500 包。
  全局最多 512 类型、2048 结构和 20,000 个选中协议包。留样上限之后继续计数，不推断全量历史。
- 写入队列最多 8 MiB，单入站帧最多 1 MiB，解析缓存最多 2 MiB。记录丢弃数和原因，写入拒绝
  会释放留样额度。磁盘写入/状态写入失败明确停止并返回非零退出码；收尾失败也会结束 `done`。
- `status.json` 每 10 秒原子更新：开始/更新时间、PID、运行状态、最后收包、连接/重试、
  不完整包与跳过帧、磁盘/队列量、各类型收到/留存计数及待配对证据。
  `status` 命令将 30 秒未更新标为 `stale-status`，避免把遗留 `running=true` 当作仍在运行。
- 首次及每小时读取固定的公共 `comm_chatmsg_w.json`；请求不带凭据、不跟随重定向，
  最长 8 秒/512 KiB，只解析 JSON。仅内容变化时保存配置快照、时间、来源和 SHA-256；
  配置不可用不会中断 Socket 采样。其他皮肤配置尚未建立快照。
- 原始资料仍在 Git 忽略目录，本机权限沿用 `0700/0600`；不上传、不提交。持久化登录态
  消息前确认实际保存字段与来源边界；清理历史数据仍需用户授权。

### 长期工具命令

从仓库根目录运行；`capture` 首先输出本轮目录，`status` 与 `replay` 不建立网络连接。

```sh
node packages/douyu-web-enhancer/tools/socket-archive.mjs capture --room 12306 --hours 24 --max-mib 256
node packages/douyu-web-enhancer/tools/socket-archive.mjs status packages/douyu-web-enhancer/.local/socket-archives/<本轮目录>
node packages/douyu-web-enhancer/tools/socket-archive.mjs stop packages/douyu-web-enhancer/.local/socket-archives/<本轮目录>
node packages/douyu-web-enhancer/tools/socket-archive.mjs replay packages/douyu-web-enhancer/.local/socket-archives/<本轮目录>
```

`stop` 写入本地 STOP 文件，采集器在下一次状态检查时停止，最长约 10 秒；运行终端内 Ctrl-C
也可停止。重放按完整 JSONL 记录重算已留存包，不再二次按限额抽样；损坏/截断行单独计数。
总收包量以原始 `status.json` 为准，重放不能恢复未选中的包。进程强制结束或 Mac 休眠的空档
不能补回，当前只可从状态时间/最后收包/连接记录发现缺口，尚无休眠原因归因或自动补采。

## 2026-10-02：16 房间与 5 GB 总预算

### 多房资源与覆盖统计

- **总上限 5,000,000,000 字节**（十进制 5 GB）：启动前扫描既有 `socket-archives`、
  `socket-samples`、`socket-plans` 文件占用并扣除。本轮旧资料占用 1,664,322 字节，剩余
  4,998,335,678 字节包含所有房间的新 JSONL、两份 2 MiB 状态文件预留及 4096 字节 STOP
  预留；序列化开销按实际字节计入。达到总预算全停，不自动删除。CLI 检测到鲜活的其他
  采集器时拒绝启动；预算不包含用户或其他程序随后额外写入的文件。
- 每房写入队列 2 MiB，共享队列 48 MiB；单房背压不会挤占全部容量。仍按 10 分钟/16 MiB
  分段，保留完整 JSONL 行。一个房间连接失败可以独立停止，共享磁盘故障使全部停止。
- 每房启动间隔 350 ms；重连使用原有最多 20 次/最长 60 秒退避，加 0.75–1 倍抖动。
  只发送匿名登录、进组及心跳控制包，无账号关注、发言或付费动作。
- 每房最多 512 类型、2048 结构、100,000 个选中包。普通/目标/未知的类型与结构额度沿用
  单房模式，但**每个整点更新一次**，避免下午已耗尽配额而晚间同类新消息不留样。
  整轮包上限不会重置；迟到的写入失败只回收所属小时的预留，已收总数一直统计。
- 公共 `comm_chatmsg_w.json` 首次及每小时全局只查一次，内容不变不重复落盘；每条房间记录
  标记房间与已知配置 SHA-256，首次配置完成前为 null。单房停止不取消其他房间需要的快照。
- 覆盖按 CST 早间 06–12、午间 12–18、晚间 18–24、夜间 00–06 记录实际收到的普通弹幕、
  特殊弹幕、礼物和进场数量。只有连接或心跳的房间不能当作有互动覆盖，更不能证明主播在播。
- 状态调度延迟超过 30 秒记录观察空档；仅报告时间缺口，不推断一定是休眠。关闭电脑、断网
  或进程退出期间的消息不能补回；没有常驻服务、自启或自动恢复已停止进程。
