# Douyu Web Enhancer 决策记录

## DWE006：控制中心是既有状态的页内投影，不是第二套 runtime

**日期：** 2026-09-16

**决策：** 控制中心使用本地打包 Lit 的单一开放 ShadowRoot，固定在视口右缘并以覆盖层打开；不引入 CDN 或
成品 UI 套件。普通页始终可见，直播间有可见弹幕栏时面板宽度受其左缘限制；网页/原生全屏只剩纯直播画面时
入口与面板隐藏。所有开关继续写入既有 SettingsStore，实际状态来自 FeatureRuntime/Diagnostics，自动化账本、
锁和审计仅只读展示。每日自动化从关闭到开启必须确认，因其保持“启用即自动执行”的既有语义。

**原因：** 用户确认需要一个可持续承载未来迁移功能、动画与状态反馈的一致 UI，同时不能让集中入口取代弹幕
和播放器附近的高频控件，也不能在观看纯画面时遮挡内容。

**后果：** Settings v6 将网页全屏偏好和自动荧光棒目标房间纳入规范设置；旧键只读迁入、不长期双写。
控制中心不会提供导入、全量清除、恢复默认或弹幕历史数据库管理；这些风险操作另立契约。

## DWE005：每日账号动作必须即时读取可变凭据并保留补偿状态

**日期：** 2026-09-14

**决策：** 同一任务包含多个账号写动作时，不缓存页面启动时的 CSRF cookie；每个动作发出前重新读取。
若任务临时改变账号状态再恢复，必须在第一步成功后立即持久记录“待恢复”，恢复成功后才清除；升级时
也要识别旧版本审计/任务状态形成的残留。页面中断、失败冷却和已失效接口必须产生可解释的有界日志。

**原因：** 0.9.0 的固定关注任务成功关注后复用了旧 CSRF，取消关注失败；下一次仅凭当前关注列表会把
脚本造成的残留误认为用户原始状态。自动荧光棒还把完整响应写进审计，超出判断任务价值所需的信息。

**后果：** 每日自动化共享锁、状态账本和 toast 的理念，但每个有临时副作用的任务还必须实现自己的
补偿标记。日志默认只保存结果、数量、错误和必要目标，不保存完整接口/WebSocket 数据或用户标识。

## DWE002：单一状态所有者与结果导向验收

**日期：** 2026-09-02

**决策：** 每个迁移功能必须声明唯一规范状态所有者。当前简洁模式使用各自的 GM 设置作为
规范状态；runtime、页面按钮、CSS 和 DOM 结果只能由其派生。CSS 注册已经能够表达静态启停时，
不再增加根节点属性作为第二道启用门控。动态 DOM 重建只重新挂载必要入口，动态页面模式只同步
对应布局状态。

迁移完成必须同时具备配置、运行时、页面结果和用户体验四层证据。结构存在或自动化测试通过不能
代替真实页面的计算样式、几何结果及相邻保留区域检查。

**原因：** `0.4.2` 中 GM 设置、runtime、CSS 和按钮均显示简洁模式已启用，但静态 CSS 又依赖
斗鱼可能清理的 `<html data-dwe-*>` 属性，造成刷新后按钮开启而礼物栏、排行榜和弹幕前缀恢复
显示。原有测试还把根属性存在误认为正确结果，没有验证用户实际看到的页面状态。

**后果：** 新增状态层、永久 observer、定时器或 DOM 标记必须说明必要性和验证方法；能由静态
CSS 自动覆盖的后来节点不再进入 observer。`0.4.3` 删除静态功能的多余根属性门控，并以真实
页面计算样式完成回归验证。

## DWE001：功能迁移默认保持用户可感知的交互契约

**日期：** 2026-09-01

**决策：** DouyuEx 功能迁移的验收范围从“核心行为可用”扩展为完整迁移契约：核心行为、
入口位置、操作步骤、状态反馈、默认值和持久化方式。页面中的高频开关优先保留在原功能附近；
Tampermonkey 菜单只保留诊断、低频全局设置或页面入口失效时的兜底。省略或改变旧交互时，
必须记录旧方案、新方案、理由和可验证的优化目标，并在用户确认后才视为有意变更。

**原因：** 简洁模式首版只迁移了 CSS 行为，把“拉高弹幕区”“隐藏弹幕前缀”和“隐藏礼物栏”
全部放进 Tampermonkey 菜单。虽然核心效果存在，但高频入口远离操作对象、状态不可见，功能增多后
还会让扩展菜单失去可用性。架构现代化应替换轮询、全局变量和不可撤销 DOM 写入，不应默认改变
已经有效的用户操作路径。
