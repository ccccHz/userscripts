# Douyu Web Enhancer agreement

本 package 将归档 DouyuEx 迁移为现代、轻量、可诊断的 userscript。归档代码、实际运行表现和用户提供的截图共同构成体验基准。

## 迁移原则

- 默认保持原版的核心行为、入口、默认值、反馈和持久化；斗鱼页面变化使旧方案失效时采用等价实现。
- 可以重写内部架构，也可以在用户明确确认后优化或超越原版；不得以工程便利自行改变已冻结体验。
- 实现前只读取当前 feature 在 `docs/migration/features.json` 中的目标条目及其直接引用；其他路线图、历史、研究和验证记录按需读取，不默认全量加载。
- 同一区域或同一操作路径的能力应共同检查体验，但不强制合并状态所有者或代码模块。

## 实现边界

- 每个功能有唯一规范状态源；设置、runtime、UI、CSS 和 DOM 标记由它派生并可重复恢复。
- 页面写入可撤销、幂等；CSS 能解决时不使用 observer。必须观察时优先共享、限频，避免永久轮询和自激。
- 一次性体验在成功、明确降级或用户接管后停止；只有契约规定的新生命周期事件才能重启。
- 页面高频功能保留页面内入口；GM 菜单只作低频设置、诊断或 UI 不可用时的兜底。
- 修改产物时提高版本，保持 `userscript.publish=false`，不得未经确认扩大 `@match`、`@connect` 或 `@grant`。

## 验收

- 使用修改后的 `dist` 实际验收冻结契约，至少检查核心操作、刷新/持久化、相关页面模式和手动接管后的行为。
- 自动化测试、设置值或 DOM 存在不能单独证明体验完成；未执行的真实路径标为 `verifying`。
- 运行 package 相关检查，并在交付前运行仓库全量 `pnpm validate && pnpm test && pnpm type-check && pnpm build`。
