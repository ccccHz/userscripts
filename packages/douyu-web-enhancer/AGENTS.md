# Douyu Web Enhancer agreement

本 package 将归档 DouyuEx 迁移为现代、轻量、可诊断的 userscript。归档代码、实际运行表现和用户提供的截图共同构成体验基准。
该 package 的调度中心只处理 DouyuEx / `douyu-web-enhancer` 范围；收到其他 userscript 需求时应转到对应任务或调度中心。新功能、迁移、修复或“继续”均先读 `docs/task-routing.md`。

## 迁移原则

- 默认保持原版的核心行为、入口、默认值、反馈和持久化；斗鱼页面变化使旧方案失效时采用等价实现。
- 不使用未定义的“原版”作为事实源：契约必须明确区分归档 DouyuEx、当前斗鱼官方体验和当前增强脚本实现；三者冲突时按用户确认的体验基准执行。
- 迁移交互或 UI 前必须先确认精确的交互表面和当前真实 DOM。若要求“和官方一样”，等价范围默认包括文案、图标、结构、顺序、位置、可见状态和交互反馈，除非契约明确排除。
- 可以重写内部架构，也可以在用户明确确认后优化或超越原版；不得以工程便利自行改变已冻结体验。
- 实现前只读取当前 feature 在 `docs/migration/features.json` 中的目标条目及其直接引用；其他路线图、历史、研究和验证记录按需读取，不默认全量加载。
- 同一区域或同一操作路径的能力应共同检查体验，但不强制合并状态所有者或代码模块。

## 实现边界

- 每个功能有唯一规范状态源；设置、runtime、UI、CSS 和 DOM 标记由它派生并可重复恢复。
- 页面写入可撤销、幂等；CSS 能解决时不使用 observer。必须观察时优先共享、限频，避免永久轮询和自激。
- 一次性体验在成功、明确降级或用户接管后停止；只有契约规定的新生命周期事件才能重启。
- 页面高频功能保留页面内入口；GM 菜单只作低频设置、诊断或 UI 不可用时的兜底。
- package 版本遵循仓库级的发布声明门禁：验证中的构建不升版本；仅在最新 `dist` 通过约定浏览器路径且获用户验收或发布授权后升版本。保持 `userscript.publish=false`，不得未经确认扩大 `@match`、`@connect` 或 `@grant`。

## 验收

- 浏览器检查、实际页面验收和 localhost 隔离夹具默认使用 Codex 内置 `@Browser`（创建标签页使用 `iab`），不因已有 Chrome 标签或熟悉工具而优先使用外部浏览器。仅在内置浏览器不可用、缺少必要能力或明确进行 Chrome 兼容性验收时回退；回退前说明具体原因，并在验收记录注明浏览器。浏览器工具名或数字 ID 不能证明其为内置浏览器，应核对所选 surface。
- 浏览器验收前确认实际加载的是主项目目录本轮最新 `dist`；内置浏览器 DEV 未安装或不一致时先报告，不静默改用 Chrome 或其他工作区产物。已取得充分证据的路径不因更换浏览器默认值而机械重跑。
- 使用最新修改后的 `dist` 实际验收冻结契约，至少检查核心操作、刷新/持久化、相关页面模式和手动接管后的行为；手感类交互还须由真实输入确认。
- UI 等价验收必须在约定的真实交互表面触发目标功能，对照官方样本检查文案、图标、顺序、位置和状态变化；邻近 DOM 数量、开关注册或单元测试通过不能代替该路径。
- 自动化测试、设置值或 DOM 存在不能单独证明体验完成；未执行的真实路径标为 `verifying`。
- 运行 package 相关检查，并在交付前运行仓库全量 `pnpm validate && pnpm test && pnpm type-check && pnpm build`。
