# 调度中心任务编排

本文件只约束调度方式，不替代模型的工程判断。目标是通过清晰的上下文隔离和完整验收，减少用户纠偏与跨任务返工。

## 当前实验配置

- 调度中心保持当前模型配置。
- 独立执行任务显式使用 `gpt-5.6-terra` / `high`；这是可调整的实验参数，不是永久结论。
- 每个任务记录实际模型、推理等级和可获得的额度数据；无法取得精确 token 时只写估算并标记污染。

## 选择任务形态

- **独立可见任务**：完整 feature、跨阶段实现、需要浏览器验收或用户反馈、需要单独统计成本的工作。
- **内部 subagent**：只读检索、API 调研、独立审查、测试矩阵等边界明确且可压缩为短结论的辅助工作。
- **调度中心直接完成**：几分钟内可完成、不会修改 package 功能或污染主要上下文的检查与规则维护。

同一 feature 的实现、直接修复和补充验收继续其独立任务；新 feature 或已混杂的上下文新建任务。subagent 只能复用原辅助角色，不能接管 feature 主线。

## 派发流程

1. 调度中心先从归档源码、当前页面、代码和既有证据整理事实，只向用户询问会改变体验、范围、状态或验收的问题。
2. 反复澄清实质性歧义后，向用户复述并确认一份书面冻结契约。契约至少包含：
   - 原始体验目标和可见成功结果；
   - 原版行为与当前实现；
   - 必做范围、非目标和保留区域；
   - 状态、持久化、触发、用户接管及失败边界；
   - 可在浏览器复现的验收步骤与所需授权；
   - 相关源码、契约、测试和文档入口。
3. 创建侧栏可见的独立任务，显式传入当前实验模型。只提供冻结契约、必要路径、已知证据、权限边界和验证命令，不复制整个调度历史。
4. 执行任务在同一契约下完成代码、测试、文档和可安全执行的浏览器验收。工程细节自主决定；会改变体验或范围的歧义返回调度中心确认。
5. 调度中心对实际产物做风险导向的独立复验：核心路径、刷新/持久化、已知易错边界和用户手动接管。无需机械重复全部测试矩阵。

one-shot 指同一独立任务可自行迭代直至交付，不需要用户反复纠正核心体验；不表示只能有一次模型回复。受账号授权、安装或罕见自然事件阻塞时可保持 `verifying`，但不得把普通核心路径遗漏包装成完成。

## 记录

在 `docs/task-execution-metrics.md` 记录任务 ID、实际模型/推理等级、起止时间、实现与返工轮次、测试和浏览器验收耗时、未覆盖项及可获得的额度变化。记录只服务比较，不为制造样本重复已经完成的代码或账号动作。

可逆、非账号性的契约内浏览器操作可直接用于验收。发送消息、签到、送礼、关注、登录、付费、修改账号状态或删除数据仍须逐项获得用户授权。
