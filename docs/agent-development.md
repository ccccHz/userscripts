# Agent 本地开发与长期自用约定

本文件记录用户于 2026-10-22 确认的使用方式及相应流程。根 AGENTS.md 是执行入口，[git-workflow.md](git-workflow.md) 定义 Git 规则。此前要求稳定快照、双入口和逐次交付记录的方案已取消，不作为日常必经流程。

## 项目和用户习惯

- 单人维护的 userscript monorepo，开发、诊断、构建和整理基本由 agent 完成；多个 package 各自只有一条持续开发线。
- 脚本几乎都是长期自用，油猴 @require 本地文件，频繁更新并长期使用开发版。这是正常使用方式，不需要为每次修改建立正式发布流程。
- 用户决定需求与体验，必要时协助真实输入验收；agent 对源码、构建、运行入口和后续收尾负责，不能把分支追踪、复制文件、恢复路径的负担转给用户。
- 常规已授权开发自主执行，减少重复确认。同一模块后续工作续用原负责人；无效自动化不能长时间重复，需及时提出具体人工协助。

## 评价与目标

monorepo 适合本项目，无需因为多个 package 同时维护而拆仓库。问题在于源码分散、已完成工作未及时提交/集成、实际加载文件与当前源码失配；不是长期使用开发版本身有问题，也不是未推送直接导致功能消失。

抖音事件：worktree 新源码仅复制 dist 到主目录，后续主目录用旧源码构建覆盖，菜单消失。根本修复是有效源码与构建入口收敛，不能靠反复复制产物维持。

目标：一个源码主线、固定本地入口、小步更新、容易定位和恢复。不要额外建立长期稳定/测试双轨、每次提升审批、庞大版本台账或调度体系。

## 日常循环

1. 定向读取根与 package 约定，确认当前分支、未提交改动、目标 package 负责人及已知 @require 来源；不默认翻全部历史。
2. 在有效源码上修改，检查受影响范围，定向构建该 package。完成可说明的小步改动及时提交，不等公开发布；不提交其他任务文件。
3. 页面功能完成“本次 dist → 核对实际入口 → 刷新页面 → 核心操作”。构建成功不能替代实页证据；无法操作时说明未覆盖项并具体请求帮助。
4. 简短汇报改动、验证和未完成项。常规本地更新不是公开发布，不要求每次请用户批准一次“自用提升”。

默认油猴固定读取 `/Users/chz/myWorkSpace/myJS/直播插件/userscripts/packages/<name>/dist/` 中对应产物。一个日常脚本入口即可；除非确需隔离试验，不要求安装两份脚本。代理权限看最外层元数据，不只看 require 文件。

构建更新该 package 的日常使用文件是预期行为；禁止的是从过期源码覆盖、跨任务误覆盖或未经确认更换入口。主目录旧分支尚未收敛时，先确认源码与入口关系，不得仅因“标准路径”就用旧源码重建。现有 worktree 入口保持到安全集成和验证完成，之后再收敛；不能为执行新规则强行切分支或改代理。

## 最少的版本与恢复措施

- 本地提交是主要版本记录。相同 @version 不代表相同代码；需要排查或交接时使用提交、dirty 状态和产物哈希定位，不要求每次更新都做哈希台账或升版。
- 构建前保留上一份已知可用产物作为快速恢复手段，可覆盖同一个备份，不必无限积累。大改动、难回退的试验或用户要求保留时，再建立明确基线/tag/独立快照。
- 源码与构建依赖能够从提交重建是长期恢复依据，上一份产物不能替代源码提交。未提交构建如需长期保留，应同时保存足够的源码差异，不能仅标 HEAD 就宣称可复现。
- 出现回归由原负责人修复；需要临时恢复时核对产物来源及依赖，不丢弃其他人的源码、不自行回退整个共享 checkout。恢复旧产物后说明源码/产物暂时不一致及后续修复。
- 推送是备份，不是本地使用前提。依已有授权在合适阶段集中备份；未获授权不自动推送，也不因此停止本地开发。不把“已提交”说成“已远端备份”。

## 文档保持轻量

优先复用 package 现有 README、TODO 或状态文档，不强制新建 delivery.md。只有长期状态发生变化时更新少量必要事实：

- 当前有效源码所在位置（标准主目录/main 时无需反复抄写）。
- 实际加载入口，特别是临时 worktree、代理或权限差异。
- 尚未集成的工作、阻塞项与下一步。
- 特别保留的可用基线，仅在需要时记录。

一次性检查结果放任务回复或既有验证文档，不复制成多份事实来源，不记录凭据或私人页面数据。

## 现有积累的收敛

先盘点实际加载路径、保留正在使用的产物，再逐个 package 识别有效源码与未提交工作，提交并集成到 main，从该源码重建及实页复验；必要时迁回固定主目录入口。确认引用解除、无唯一未保存数据后才清理临时工作区，遵循授权。

本文件修改不代表现存分支、入口、备份和产物已经整理完成；后续由相应负责人执行，不在文档调整时顺带切换现场。
